# Architectural decisions

Create a short architectural decision record when a choice:

- changes a durable system boundary;
- introduces a hard-to-reverse dependency;
- affects security, privacy, or data ownership;
- changes the Watch independence requirement;
- supersedes guidance that future contributors might otherwise rediscover.

Use `YYYY-MM-DD-short-title.md` with:

1. status and date;
2. context and accepted user story;
3. decision;
4. alternatives considered;
5. consequences;
6. evidence or revisit trigger.

Do not create an ADR for routine implementation details. Keep current guidance
in the relevant document linked from [../README.md](../README.md); an ADR
preserves why, not a second copy of what.
